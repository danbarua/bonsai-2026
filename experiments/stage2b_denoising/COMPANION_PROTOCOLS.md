**Status: frozen. Committed before either protocol has produced a
number.** These are the two companion protocols named at the end of
`AUDIT_PROTOCOL.md`. Same rule applies: nothing here may be changed once a

# Protocol 1 — ARM/x86 propagation stress set

## What this measures, and what it does not

Phase A moved encoding onto Apple Silicon; ladder stages 1 and 2 encoded
on Colab x86. The recorded cross-architecture comparison (`FINDINGS.md`,
"Measured, before the decision was acted on") found 93.4% of coordinates
identical and a **max 3 ULP** difference (4.441e-16), against
within-architecture results that were bit-exact in both directions —
same machine twice, and two separate Colab sessions.

That comparison was made at the **encoding** stage only, on the stage-1
corpus, and it is the input to this protocol rather than a substitute for
it. The open question it does not answer is propagation: whether a 3-ULP
encoding difference stays negligible after the ODE solve, the ridge
prediction, and the evolved-minus-pre contrast — the quantity the audit
actually triggers on.

This protocol is a **worst-case** probe, deliberately. The stress set is
built to be adversarial, so its numbers are an upper bound on propagation
and are not representative of the corpus. It is not a random sample and
must never be reported as one.

## Construction of the stress set (deterministic, frozen)

Four components, unioned, then deduplicated by official KMNIST training
index and sorted ascending. The sorted deduplicated index array IS the
stress set, and it is written to the artifact so the set is auditable
rather than re-derived.

| # | component | rule | size |
|---|---|---|---|
| A | largest cross-architecture encoding discrepancy | the images with the largest per-image **max** absolute coordinate difference between the ARM and x86 encodings recorded in the existing comparison; ties broken by official index ascending | 100 |
| B | convergence-tail stress cases | **every** image whose Phase A final-Delta is strictly greater than 0.0, taken from the regenerated 60,000-image artifact's `deltas` array | all, capped (see below) |
| C | per-class floor | for any KMNIST class with fewer than 20 images after A ∪ B ∪ D, the lowest-indexed images of that class are added until it has 20 | as needed |
| D | seeded stratified random | 20 per class, 200 total, drawn with `numpy.random.default_rng(42)` from each class's official-index list in ascending order via `rng.choice(indices, size=20, replace=False)`, classes visited 0..9 in order | 200 |

**Cap on component B**, frozen here because the count is not yet known:
if more than 500 images have final-Delta > 0, take the 500 largest by
final-Delta, ties broken by official index ascending, and record both the
cap and the true count. The 54,000-image run measured 79 (0.146%), so the
cap is expected to be inert; it exists so the set size cannot be decided
after seeing the number.

**Naming, per `AUDIT_PROTOCOL.md`.** These are *convergence-tail stress
cases*. The earlier "basin-boundary candidates" characterisation was
retracted as unsupported: an encoder-contraction residual is a different
dynamical quantity from proximity to an evolution-flow boundary, and
nothing measured here speaks to the latter.

**Where component A comes from if the recorded comparison is
unavailable.** It was measured on the stage-1 corpus, not the stage-3 one.
If the per-image differences are not recoverable from the record, A is
regenerated by encoding the stress set's other components on both
architectures and is then reported as regenerated, with the substitution
stated — never silently replaced by a different rule.

## Comparison procedure

**First comparison — frozen ridge coefficients, both architectures.**
Identical, already-fitted ridge coefficients are applied to the
ARM-derived and the x86-derived features. This isolates numerical
propagation from refit variation: a refit on ARM features would produce
different coefficients, and the resulting difference would confound the
two mechanisms with no way to separate them afterwards.

Reported max absolute differences, at each stage of the chain:

1. encoding (the 505-dim restricted phase vector)
2. evolved features, **per graph** (`T`, `lattice`, `rewired`,
   `curr_random`)
3. prediction
4. per-image MSE
5. the evolved-minus-pre contrast `Delta_g`

All five, always, whatever any one of them shows. Reporting only the
stages that stayed small would make the chain unreadable.

## Consequence rule (frozen, before any number)

The propagation measurement is **descriptive** at stages 1–4. Stage 5 has
one pre-committed halt condition:

> If the max absolute cross-architecture difference in `Delta_g`, for any
> graph, **exceeds the audit's frozen contrast threshold** (`4.604761e-10`,
> `AUDIT_PROTOCOL.md` Freeze 1 at M=100), then cross-architecture
> numerical noise is not separable from the effect the audit tests for,
> and that triggers renewed interpretation review before Stage 4.

The threshold is borrowed, not invented: it is already frozen, already
derived analytically from the metric's algebra and a recorded `d`, and
already the line below which a difference is called implementation dust.
A propagation difference at or above it would mean the audit cannot
distinguish its own signal from which machine did the encoding.

Deliberately **not** claimed in advance: that the measurement will come in
below that line. The encoding-stage result (3 ULP, eight or more orders
below the solver's `rtol=1e-6`) is a reason to expect it and is not
evidence of it, exactly as `AUDIT_PROTOCOL.md` declines to assert
robustness across orders of magnitude of `M` before measuring it.

# Protocol 2 — `ABS_CONV_EPS` sensitivity

## What this measures

`ABS_CONV_EPS = 1e-12` is the absolute-convergence escape added to the
encoder gate after the ratio-near-a-floor defect (`FINDINGS.md` Part 2–3;
CLAUDE.md principle 23). A threshold introduced to fix a failure is
exactly the kind of constant that needs its sensitivity shown rather than
asserted, because the value was chosen after seeing the failure it
resolves.

## Recomputation (frozen)

The gate verdict is recomputed **from the stored per-image final-Delta
arrays** — no re-encoding — at

    eps in {1e-10, 1e-11, 1e-12, 1e-13}

crossed with every step count for which a stored array exists: the five in
`diagnose_encoder_gate_failure.py`'s `STEP_COUNTS` (75, 150, 300, 600,
1200), and the ladder's own `encoder_gate_s{steps}` artifacts.
`evaluate_rho_gate` is called unmodified, varying only its existing
`abs_conv_eps` parameter — no reimplementation of the gate, per CLAUDE.md
principle 16.

The output is one table: rows are step counts, columns are eps, cells are
`PASS`/`FAIL` with `rho`, `median_delta_clean` and `median_delta_noisy`
alongside. Every cell is reported, including the ones that agree.

**The quantity of interest is where the verdict FLIPS**, at the locked
`ENCODER_STEPS=1200` and at every other step count. If the verdict at
1,200 is invariant across all four eps, that is the result. If it is not,
the eps at which it changes and the direction of the change are the
result, and they are reported as such.

## The four justification axes (all four required)

`AUDIT_PROTOCOL.md` requires 1e-12 justified against four axes. Each gets
a written paragraph with its own measured numbers; three of them exist,
and the fourth is the one previously dropped in consolidation and
reinstated here.

1. **float64 precision.** Observed numerical dust in the final-Delta
   series spans 1e-14 to 1e-16. 1e-12 sits above that band, so a value
   below it cannot be distinguished from dust.
2. **Scale of the phase-update diagnostic.** The smallest meaningful
   measured final-Delta anywhere in this project is 2.177e-07 (clean, 150
   steps, stage 1). 1e-12 is five or more orders below it, so the escape
   cannot fire on a genuine, still-converging signal.
3. **The encoder implementation.** What magnitudes the update rule can
   produce at all: the encoder is a contraction toward a fixed point, with
   measured residual against the 1,200-step result falling
   8.370e-07 → 8.062e-13 → exactly 0.0 at 300 / 600 / 1,200 steps. The
   axis to write up is the relationship between that decay and the
   threshold — specifically, at which step count the residual first
   crosses 1e-12, and whether the escape is therefore describing
   convergence or describing the float64 floor.
4. **Downstream feature sensitivity.** How a final-Delta of magnitude eps
   propagates into the cos/sin features and then into the ODE solve. The
   reference points are the solver's `rtol=1e-6` and the 54,000-image
   worst case of 2.468e-10, which sits 4,053x below it. The axis to write
   up is what a phase residual of 1e-10, 1e-12 and 1e-13 does to the
   evolved features and to `Delta_g` — i.e. whether any eps in the swept
   range is large enough to matter downstream at all.

## Consequence rule (frozen)

**`ABS_CONV_EPS` does not change as a result of this table**, on the same
footing as `AUDIT_PROTOCOL.md`'s "the 1,200-step budget stays frozen
regardless of every number this audit produces". What may change is the
scope of the claim made about the gate.

One halt condition: if the verdict at the locked `ENCODER_STEPS=1200`
differs across the swept eps range, the gate's PASS is contingent on a
constant chosen after the failure it resolves, and that triggers renewed
interpretation review before Stage 4.

## Provenance and reporting

Both protocols run under the fingerprint contract
(`stage2b_fingerprint.py`): the stress-set index array, every reported
maximum, and the full sensitivity table are published with a manifest, so
the numbers carry the code that produced them.

Both are reported in `FINDINGS.md` with their construction stated inline —
the stress set is adversarial by design and the sensitivity table is a
recomputation, and a reader who meets either number without that framing
will read it as a corpus-level property, which neither is.
